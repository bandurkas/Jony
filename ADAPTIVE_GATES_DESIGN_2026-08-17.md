# Adaptive Gates — динамический подбор параметров входа (дизайн, 2026-08-17)

## Сдвиг парадигмы (запрос пользователя)

Не искать один «идеальный» конфиг на всю историю — рынок меняется. Вместо
этого: параметры входа перевыбираются регулярно по релевантности последних
2–4 недель (с проверкой стабильности на 3–6 мес), решением специального
агента-«Тюнера». Это позволяет ловить удачные окна (как ETH:P WR 88% в июле),
вместо того чтобы усреднять их с чужими режимами 2-летней давности.

## Ключевой методологический принцип

**Валидируем ПРАВИЛО переключения, а не параметры.** Погоня за «последними
2 неделями» без проверки = покупка пика удачи конфига (classic walk-forward
overfitting). Поэтому:
1. Правило выбора — детерминированное (скрипт), его можно честно прогнать
   walk-forward по 2 годам БЕЗ lookahead: на каждую дату перевыбора t
   используются только сделки, ЗАКРЫТЫЕ до t.
2. Gate: адаптивное правило обязано побить лучший статический конфиг
   (кандидат C из Phase 7) на том же периоде/реплее. Не побьёт — REJECTED,
   остаёмся на статике.
3. LLM (Advisor/Тюнер) — НЕ выдумывает параметры. Он выбирает в рамках
   правила и белого списка (см. ниже) и может только сузить/отложить.

## Архитектура (3 слоя)

### Слой 1: Белый список конфигов (safety rail)
72 комбинации на монету из Phase 7 грида: ret7d∈{0.5,1,1.5,2,3,999} ×
vol∈{0.30,0.40,0.50,0.60} × regime∈{R,RT,RTT}, только PUT. Тюнер выбирает
ИЗ списка — произвольные значения запрещены. Риск-слой (per_key_cap=1,
margin cap, CB, advisor-стопы) агенту НЕ подчиняется — вообще вне его прав.

### Слой 2: Детерминированный селектор (ядро, бэктестится)
Каденция: раз в неделю + внеплановый пересчёт при wake-триггере (см. ниже).
На дату t, для каждой комбинации белого списка, по сделкам с exit_ts <= t:

| Окно | Роль | Что считается |
|---|---|---|
| 1 день | wake-триггер, НЕ выбор | спайк rv24 / движение спота >N% → внеплановый пересмотр + временное ужесточение (posture tight) |
| 3 дня | wake-триггер, НЕ выбор | серия убытков активного конфига (>=3 подряд) → внеплановый пересмотр |
| 1 неделя | скоринг (relevance) | fixed-lot PnL, n, WR комбо |
| 2–4 недели | ГЛАВНОЕ окно скоринга | fixed-lot PnL (вес 0.5 на 2 нед + 0.3 на 4 нед) |
| квартал (13 нед) | фильтр стабильности | вес 0.2 + floor: PnL_13w > -$F |
| полгода (26 нед) | жёсткий floor | PnL_26w > -$F, иначе комбо исключается из выбора |

Правило выбора:
1. Отфильтровать комбо, провалившие floors (13w/26w) или n_4w < N_min
   (минимальная активность — по мёртвому окну выбирать нельзя).
2. Ранжировать по взвешенной сумме рангов PnL: 0.5*rank(2w) + 0.3*rank(4w)
   + 0.2*rank(13w).
3. Гистерезис: сменить активный конфиг ТОЛЬКО если претендент лучше на
   >= H перцентилей рейтинга ИЛИ активный конфиг провалил floor. Иначе
   держим текущий (защита от дёргания и комиссионного шума).
4. Если ни одно комбо не прошло фильтры — торговля стороной выключается
   (честный «нет сегодня эджа» вместо натяжки).

Точные значения F, N_min, H, весов и каденции — НЕ подбираем вручную:
их выбирает мета-бэктест (walk-forward по 2 годам, сетка небольшая,
критерий — робастность по кварталам, обе сигмы).

### Слой 3: LLM-Тюнер (контекстный надзор, НЕ бэктестится — ограничен)
Расширение advisor.py (или отдельный tuner.py тем же паттерном: hourly/daily
тик, forced tool call, jsonl-аудит). Права СТРОГО ограничены:
- видит: топ-3 комбо от детерминированного селектора + их метрики по всем
  окнам + рыночный контекст (funding, OI, IV-RV, дистанции до хай/лоу,
  календарь макро);
- может: (а) подтвердить #1; (б) выбрать #2/#3 с письменным обоснованием;
  (в) наложить вето на смену (остаться на текущем); (г) запросить tight
  posture. НЕ может: выдумать параметры вне белого списка, отключить
  риск-слой, поднять размер.
- каждое решение пишется в аудит + self-scoring (как /advice/score):
  через неделю сверяем «что дал выбор LLM vs что дал бы #1 селектора» —
  копится честная статистика, полезен ли LLM-слой вообще.

### Live-механика (Track B, после gate)
- tuner пишет активный конфиг в bot_control (gate_params_json, TTL 8 дней);
  loop.py читает его каждую минуту; при протухании/отсутствии — fallback
  на статический дефолт (кандидат C) — fail-closed, бот не останавливается.
- Mission Control показывает активный конфиг, кто/когда выбрал, следующий
  плановый пересмотр.
- Смена конфига НЕ трогает открытые позиции — только новые входы.

## План
- **Phase A (сейчас, research)**: дамп сделок всех 72×2 комбо на 2 года →
  walk-forward мета-бэктест правила (недельная каденция, сетка F/H/веса) →
  сравнение с статикой A/C → gate.
- **Phase B (после gate + выбора пользователя)**: Track B — tuner.py, правки
  loop.py/api, тесты, ревью, деплой, live-check. + дисплейный фикс proximity.
- **Phase C (live)**: 2–4 недели наблюдения: score LLM-слоя vs детерминизм,
  частота смен конфига, поведение в wake-триггерах.

## Открытые риски (честно)
- Меньше данных на решение = шумнее выбор; гистерезис и floors — единственная
  защита. Мета-бэктест покажет, достаточно ли её.
- 168h тенор = сделки закрываются медленно → окна 1-2 нед содержат мало
  ЗАКРЫТЫХ сделок (~5-15 на комбо) — поэтому главный вес на 2-4 нед, а не 1 нед.
- Q3-режим (общий провал put-selling) адаптация не чинит, но должна резать
  быстрее, чем статика (селектор увидит деградацию через floors) — проверим
  именно этот квартал в мета-бэктесте отдельно.
